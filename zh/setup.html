开场：“在我电脑上能跑”

开场问题

同一个仓库，同事 pnpm dev 一切正常；你这里报 SyntaxError: Unexpected token；Agent 的沙箱里又报 Cannot find module。代码一模一样，为什么结果不同？

答案方向：“代码”只是运行结果的一个输入。另外三个输入是：Node 版本、包管理器及其版本、实际安装的依赖版本（由锁文件决定）。任何一个不一致，结果就可能不同。可复现环境的做法就是把这三样都写进仓库。

第一步：用版本管理器安装 Node 会用

不要直接从官网下载安装包。你迟早会同时维护需要不同 Node 版本的项目。版本管理器让“每个项目自动用它自己的版本”成为可能。推荐 mise（一个工具管理 Node、pnpm、Python、Go 等所有运行时）或 fnm（只管 Node，极简）。

Node 的版本规律：偶数版本会进入长期支持（LTS），奇数版本只是短期的“Current”。生产项目选 LTS。截至 2026 年 9 月，Node 24 是 LTS，Node 26 将在 10 月转为 LTS。

第二步：安装 pnpm 会用

在项目的 package.json 里写上 "packageManager": "pnpm@10.x.x"（写确切版本），很多工具（包括 CI 和部署平台）会据此使用同一个包管理器版本。

第三步：编辑器——你最重要的学习工具 会用

VS Code、Cursor、Zed 或 JetBrains WebStorm 都可以。它们内置了 TypeScript 语言服务（language service）：你写代码的同时，它在后台持续做类型检查。

转型期最有用的一个习惯：悬停看类型

把鼠标悬停在任何变量、函数、组件上，编辑器会显示它的完整类型。读 Agent 生成的代码时，这是理解数据形状最快的方法——比读文档快得多。按住 Cmd/Ctrl 点击可以跳到定义，包括 node_modules 里库的类型声明。

建议安装的扩展：Biome（格式化 + Lint，或 ESLint + Prettier）、Tailwind CSS IntelliSense（样式类名提示）、Error Lens（把错误直接显示在代码行尾）。

第四步：安装一个 Coding Agent

本教程不绑定具体工具。主流的终端 Agent 有 Claude Code（Anthropic）、Codex CLI（OpenAI）、pi（开源、极简、可用 TypeScript 扩展）等，它们的工作原理相同（第 12 章会拆开讲）。安装方式各自以官方文档为准，大多支持 npm install -g。

装好后先做一件事：在一个空目录里让它“解释你刚装好的环境”——检查它能否正确运行 node -v、pnpm -v。这能确认 Agent 的执行环境和你的终端一致。

tsconfig.json：只需要看懂这几项 会用

  • strict 是最重要的一项。关掉它，TS 会退化成“带提示的 JS”，大量错误（如 null 访问）不会被发现。如果 Agent 为了消除报错去关掉 strict 或加 // @ts-ignore，这是需要你拦下来的信号。
  • noUncheckedIndexedAccess 默认不开，但强烈建议开：items[0] 可能不存在，这类 bug 在生产环境里非常常见。
  • 如果你打算用 Node 直接运行 .ts，还可以开 erasableSyntaxOnly：它禁止使用 enum 等“需要生成代码”的 TS 语法，保证类型可以被简单地剥离。

环境变量：哪些会被送到浏览器 原理

这是新手最容易犯、后果最严重的错误之一，所以即使在“搭环境”这一章，也要讲到原理层。

后端开发中，环境变量只存在于服务器进程里，天然是保密的。但在前端构建中，打包器会在构建时把代码里引用的某些环境变量直接替换成字面值，写进发给浏览器的 JS 文件里。为了防止误泄露，各框架规定：只有带特定前缀的变量才会被这样处理。

规则

带 VITE_ / NEXT_PUBLIC_ 等公开前缀的变量，等同于公开发布。API Key、数据库连接串绝不能用这类前缀。如果浏览器端需要调用 LLM，正确做法是浏览器请求你自己的服务器，由服务器带着密钥去调用（第 11 章）。

自检

1. 你在 .env 里写了 VITE_OPENAI_KEY=sk-...，只在一个“设置”页面用到它，页面还加了登录保护。安全吗？

不安全。VITE_ 前缀的变量在构建时被内联进 JS 文件。JS 文件是静态资源，不需要登录就能下载（登录保护的是页面数据，不是打包后的脚本）。任何人打开 JS 文件都能搜到这个 key。应该去掉前缀，只在服务器端使用。

2. 为什么锁文件必须提交，而 node_modules 不能提交？

锁文件记录了每个依赖（包括间接依赖）的确切版本和校验值，是“可复现”的关键；它很小，而且是文本。node_modules 可以随时从锁文件重建，体积巨大，还可能包含和操作系统相关的二进制文件。

3. Agent 为了解决一个类型错误，在 tsconfig 里把 strict 改成了 false，然后说“类型检查通过了”。你怎么评价？

这是“让检查闭嘴”而不是“修复问题”。关闭 strict 会让大量真实缺陷（如 null 访问）不再被报告。应该回退这个修改，要求 Agent 在 strict 模式下修复具体错误，并把“不得修改 tsconfig 严格选项”写进 AGENTS.md。
